# 管理员后台 · 预约管理与强制取消（手动改造清单）

> 目标：管理员能查看全部预约、按条件筛选、强制取消任意用户的预约。  
> 核心原则：**强制取消复用现有 `BookingService.cancel()`，不写第二套状态逻辑**。  
> 前置：座位管理（第一档 1）已完成；`AdminController` 已存在且带类级 `@PreAuthorize("hasRole('ADMIN')")`。

---

## 关键结论：强制取消不用重新实现

`BookingService.cancel()` 第 150-155 行已经支持管理员取消他人预约：

```java
boolean isOwner = booking.getUserId().equals(me.id());
boolean isAdmin = "ADMIN".equals(me.roleCode());
if (!isOwner && !isAdmin) {
    throw BizException.forbidden("不能取消他人的预约");
}
int rows = bookingMapper.cancel(bookingId, booking.getUserId());  // CAS: WHERE status='BOOKED'
```

而且它内部已经做了两件正确的事：

- `bookingLogMapper.insert(...)` 记录操作人 `me.id()`（管理员 id 会被如实记录）
- `AfterCommit.run(...)` 摘掉 CHECKIN/FINISH 延迟任务

**所以管理端取消接口只要把当前 ADMIN 的 `UserSnapshot` 传给这个方法即可**，一致性完全复用。面试话术："管理端取消与用户自助取消共用同一个 `cancel`，保证日志、延迟任务摘除、CAS 语义完全一致。"

> 注意一个边界：`cancel()` 只能取消 `BOOKED` 状态。如果管理员想取消"已签到/暂离中"的预约，本清单**不做**（那属于"强制结束"，语义不同且要记违约，容易破坏状态机）。列表里对这些状态只展示、不给取消按钮。这是明确的取舍。

## 一、后端改动（4 个文件）

### 1. 新增 DTO：`web/dto/AdminBookingView.java`

管理端列表要显示用户名和座位号，`BookingView` 里没有这两个字段，新建一个专用 DTO：

```java
package com.seat.reserve.web.dto;

import java.time.LocalDate;
import java.time.LocalDateTime;
import java.time.LocalTime;

/**
 * 管理端预约列表：比用户端 BookingView 多了 username / nickname，便于追溯是谁预约的。
 */
public record AdminBookingView(
        Long id,
        Long seatId,
        String seatNo,
        Long roomId,
        String roomName,
        Long userId,
        String username,
        String nickname,
        LocalDate bookDate,
        LocalTime startTime,
        LocalTime endTime,
        String status,
        LocalDateTime createdAt
) {
}
```

### 2. 修改 `mapper/BookingMapper.java`（加 1 个查询方法）

```java
/** 管理端：按日期查全部预约（JOIN 出用户名 / 座位号 / 阅览室名） */
List<AdminBookingView> listAllByDate(@Param("date") LocalDate date,
```

> `status` 传 null 表示不筛选。用 `@Param` 是因为多参数。

同时文件顶部加 import：

```java
import com.seat.reserve.web.dto.AdminBookingView;
```

### 3. 修改 `resources/mapper/BookingMapper.xml`（加 1 条 SQL）

```xml
<select id="listAllByDate" resultType="com.seat.reserve.web.dto.AdminBookingView">
    SELECT b.id, b.seat_id AS seatId, s.seat_no AS seatNo,
           b.room_id AS roomId, r.name AS roomName,
           b.user_id AS userId, u.username, u.nickname,
           b.book_date AS bookDate, b.start_time AS startTime, b.end_time AS endTime,
           b.status, b.created_at AS createdAt
    FROM seat_booking b
    LEFT JOIN lib_seat s ON s.id = b.seat_id
    LEFT JOIN lib_room r ON r.id = b.room_id
    LEFT JOIN sys_user u ON u.id = b.user_id
    WHERE b.book_date = #{date}
    <if test="status != null and status != ''">
        AND b.status = #{status}
    </if>
    ORDER BY b.start_time, b.seat_id
</select>
```

**索引说明**：`WHERE book_date = ?` 能命中 V3 加的 `idx_date_status(book_date, status)` 的最左列；再加 status 条件时是完整命中。这是阶段一那个索引的第二个受益点，面试可以串起来讲。

### 4. 修改 `web/AdminController.java`（加 2 个接口 + 注入 1 个依赖）

**a) 构造器注入 `BookingService`**（原来只有 reportService 和 seatAdminService）：

```java
private final ReportService reportService;
private final SeatAdminService seatAdminService;
private final BookingService bookingService;

public AdminController(ReportService reportService, SeatAdminService seatAdminService,
                       BookingService bookingService) {
    this.reportService = reportService;
    this.seatAdminService = seatAdminService;
    this.bookingService = bookingService;
}
```

**b) 加 import**：

```java
import com.seat.reserve.domain.SeatBooking;
import com.seat.reserve.security.UserSnapshot;
import com.seat.reserve.service.BookingService;
import com.seat.reserve.web.dto.AdminBookingView;
import org.springframework.security.core.annotation.AuthenticationPrincipal;
```

（`SeatBooking` 如果没用到可以不加；`TimeUnit` 无）

**c) 加两个接口**（放在座位管理接口之后）：

```java
// ==================== 预约管理 ====================

/** 管理端：按日期查全部预约，status 可选（不传则查全部） */
@GetMapping("/bookings")
public R<List<AdminBookingView>> bookings(
        @RequestParam @DateTimeFormat(iso = DateTimeFormat.ISO.DATE) LocalDate date,
        @RequestParam(required = false) String status) {
    // STATUS_META 之外的裸字符串直接当无条件处理会更宽松，这里选择严格：只接受已知状态
    if (status != null && !status.isBlank()
            && !java.util.List.of("BOOKED", "CHECKED_IN", "LEAVING",
                                  "FINISHED", "CANCELLED", "EXPIRED").contains(status)) {
        throw com.seat.reserve.common.BizException.badRequest("未知的状态值");
    }
    return R.ok(reportService.listAllBookings(date, status));
}

/** 管理端：强制取消预约（复用用户自助取消的同一套逻辑） */
@DeleteMapping("/bookings/{id}")
public R<Void> cancelBooking(@AuthenticationPrincipal UserSnapshot me,
                             @PathVariable Long id) {
    bookingService.cancel(me, id);   // 复用！cancel 内部已判断 ADMIN 权限并记操作人
    return R.ok(null);
}
```

**d) 在 `ReportService.java` 加一个转发方法**（让 Controller 不直接依赖 Mapper，保持项目分层风格）：

```java
private final ReportMapper reportMapper;
private final BookingMapper bookingMapper;   // ← 新增注入，改构造器

public List<AdminBookingView> listAllBookings(LocalDate date, String status) {
    return bookingMapper.listAllByDate(date, status);
}
```

> 如果你嫌绕，也可以让 `AdminController` 直接注入 `BookingMapper`（项目里 `BookingController` 就是直连 Mapper 的，有先例）。两种都行，**推荐走 Service 保持分层一致**。

## 二、前端改动（2 个文件）

### 5. 新增 `web/src/pages/AdminBookings.jsx`

参考现有 `MyBookings.jsx` 的风格（STATUS_META、DatePicker、Table 都照搬），核心差异如下：

```jsx
import { useCallback, useEffect, useState } from 'react';
import { Button, Card, DatePicker, Popconfirm, Select, Space, Table, Tag, message } from 'antd';
import dayjs from 'dayjs';
import request from '../api/request.js';

const STATUS_META = {
  BOOKED:     { text: '待签到', color: 'blue' },
  CHECKED_IN: { text: '在座',   color: 'green' },
  LEAVING:    { text: '暂离中', color: 'orange' },
  FINISHED:   { text: '已完成', color: 'default' },
  CANCELLED:  { text: '已取消', color: 'default' },
  EXPIRED:    { text: '已失效', color: 'red' },
};

export default function AdminBookings() {
  const [date, setDate] = useState(dayjs());
  const [status, setStatus] = useState(undefined);   // undefined = 全部
  const [rows, setRows] = useState([]);
  const [loading, setLoading] = useState(false);

  const load = useCallback(async () => {
    // eslint-disable-next-line react-hooks/set-state-in-effect
    setLoading(true);
    try {
      const list = await request.get('/admin/bookings', {
        params: {
          date: date.format('YYYY-MM-DD'),
          ...(status ? { status } : {}),
        },
      });
      setRows(list);
    } finally {
      setLoading(false);
    }
  }, [date, status]);

  // eslint-disable-next-line react-hooks/set-state-in-effect
  useEffect(() => { load(); }, [load]);

  async function doCancel(id) {
    await request.delete(`/admin/bookings/${id}`);
    message.success('已强制取消');
    load();
  }

  const columns = [
    { title: '座位', width: 90,
      render: (_, r) => <strong>{r.seatNo || `#${r.seatId}`}</strong> },
    { title: '阅览室', width: 120, render: (_, r) => r.roomName || '—' },
    { title: '预约人', width: 120,
      render: (_, r) => `${r.nickname || r.username || '#' + r.userId}` },
    { title: '时段', width: 130,
      render: (_, r) => `${r.startTime.slice(0,5)} - ${r.endTime.slice(0,5)}` },
    { title: '状态', dataIndex: 'status', width: 100,
      render: (s) => {
        const m = STATUS_META[s] || { text: s, color: 'default' };
        return <Tag color={m.color}>{m.text}</Tag>;
      } },
    { title: '操作',
      render: (_, r) => (
        r.status === 'BOOKED'
          ? <Popconfirm title={`强制取消 ${r.nickname || r.username} 的预约？`}
                        onConfirm={() => doCancel(r.id)}>
              <Button size="small" danger>强制取消</Button>
            </Popconfirm>
          : <span style={{ color: '#bbb' }}>—</span>
      ) },
  ];

  return (
    <Card size="small" title="预约管理"
      extra={
        <Space>
          <DatePicker value={date} allowClear={false} onChange={(d) => d && setDate(d)} />
          <Select style={{ width: 120 }} value={status} onChange={setStatus}
            allowClear placeholder="全部状态"
            options={Object.entries(STATUS_META).map(([value, m]) => ({ value, label: m.text }))} />
          <Button onClick={load}>刷新</Button>
        </Space>
      }>
      <Table rowKey="id" size="small" loading={loading}
             columns={columns} dataSource={rows} pagination={false} />
    </Card>
  );
}
```

**注意**：`useEffect` 里的 eslint-disable 注释不能省，否则 lint 报 `react-hooks/set-state-in-effect`（你项目里 `MyBookings.jsx:37-38` 和 `AdminSeats.jsx:33` 都是这么处理的）。

## 四、面试话术（可直接背）


> "管理端预约列表用一条 SQL JOIN 出用户名、座位号、阅览室名，靠阶段一加的 `(book_date, status)` 索引支撑按日期和状态的筛选。强制取消没有另写逻辑，而是直接复用用户自助取消的 `BookingService.cancel`——它内部已经判断了 ADMIN 权限、用 CAS 保证只取消 BOOKED、记录操作人到流水、并在事务提交后摘掉延迟任务。管理端和用户端走同一条路径，保证一致性。我刻意没做'强制结束在座预约'，因为那涉及记违约和状态机语义，和取消是两回事。"

## 五、常见坑

| 现象                         | 原因                                          | 解决                                                                 |
| -------------------------- | ------------------------------------------- | ------------------------------------------------------------------ |
| 前端刷新 `/admin/bookings` 404 | `SpaForwardController` 没加                   | 按第 7 节改                                                            |
| 前端刷新 `/admin/bookings` 401 | `SecurityConfig` 白名单没加                      | 按第 7 节改                                                            |
| 列表接口 500                   | DTO 字段别名没写驼峰                                | XML 里 `AS seatId` 等别名别漏，`map-underscore-to-camel-case` 已开也能兜底下划线写法 |
| 强制取消返回 409                 | 该预约不是 BOOKED（已签到/过期）                        | 正常，前端只对 BOOKED 显示按钮                                                |
| lint 报 set-state-in-effect | useEffect 里漏了 eslint-disable                | 照 `MyBookings.jsx:37` 加注释                                          |
| ADMIN 取消被 403              | 传进去的 `me` 不是从 `@AuthenticationPrincipal` 拿的 | 接口参数必须加 `@AuthenticationPrincipal UserSnapshot me`                 |
